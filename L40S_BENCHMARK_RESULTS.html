핵심 발견

1. Bottleneck shifts as opts stack — 최적화 순서가 중요

Fork 상태에선 sub-talker AR이 dominant. Batched preprocess 가 그 위 CPU overhead 를 잡으면, sub-talker AR 의 GPU bound 가 새 bottleneck. Main talker FP8 는 그 와중에 main talker compute 를 줄여서 저 bs 의 위 효과를 누적. KV cache 는 sub-talker AR 자체 (5L × 14 sub-steps × re-prefill) 를 공격해서 고 bs 의 최종 큰 점프.

2. bs-별 dominant 기여자

bs 구간Dominant 기여자이유
bs=1-4F — Main talker FP8 (−12%)
C, D — flashinfer + fusion (-5%씩)		Main talker가 step time 의 큰 비중. sub-talker 작음.
bs=8-16Mixed (F + C + D)Main / sub-talker 비중 균형
bs=32-64B — batched preprocess (−28%)
H — KV cache (−20%)		Per-request CPU overhead + sub-talker AR scaling 이 dominant

3. vLLM SDPA cuDNN dispatch 진단

3중 gate 발견:

  1. enable_gqa=True + attn_mask → fused backend 모두 거부
  2. PyTorch priority order 에서 MATH가 CUDNN 앞
  3. vLLM 전역 enable_cudnn_sdp(False) (diffusers 호환)

해결: sdpa_kernel(list, set_priority=True) + 수동 GQA expand. SDPA backend time decode bs=8: MATH 30.3μs → CUDNN 11.5μs (−62%).

부록 B — 측정 메소돌로지

  • 측정 도구: bench_qwen3_tts.py — httpx async 클라이언트로 /v1/audio/speech POST 스트리밍
  • 측정 조건: 모두 --repeats 7 --warmup 5 --bucket-warmup 3 --batch-sizes 1,2,4,8,16,32,64
  • 모드: QWEN3_TTS_SKIP_C2W=1 (audio decode 생략, sub-talker compute 비중 isolate)
  • RTF_agg: wall_total / sum(audio_durations) — length-normalized, lower = faster
  • Throughput: 12 / RTF_agg (codec 12Hz → main tokens per second)
  • Stage 별 측정: git worktree 로 각 commit 격리 후 server 재시작 + full sweep. 동일 야ml + 동일 워크로드 + 동일 GPU. 단 F 부터 FP8 yaml 사용, H 는 QWEN3_TTS_USE_KV_CACHE=1 환경변수.
  • Hardware: L40S (sm_89, Ada Lovelace, 46GB VRAM, 864 GB/s memory BW)
  • 모델: Qwen/Qwen3-TTS-12Hz-1.7B-CustomVoice, voice Vivian
  • Buckets: short (~12 chars, ~2.4s audio) / medium (~45, ~9.6s) / long (~120, ~30s)
